# Личные уведомления о работе программы

`operations_bot` — независимый read-only наблюдатель над журналами PostgreSQL. Он не вызывает API маркетплейсов и не участвует в транзакциях синхронизации.

Раз в пять минут модуль собирает завершившиеся события:

- полный цикл Wildberries и ошибки его внутренних задач;
- независимую синхронизацию документов и баланса Wildberries;
- каждое независимое Ozon-задание;
- документы и бухгалтерские отчёты Ozon, включая ошибки генерации и скачивания;
- обновление и дневной срез остатков отдельно по маркетплейсам;
- успешные и неуспешные Telegram-отчёты;
- новые наборы ошибок healthcheck и последующее восстановление; одинаковая проблема каждые пять минут не дублируется.

События складываются в `operations_event_deliveries`, а затем одним понятным дайджестом отправляются в личный чат. Очередь остаётся в БД при недоступном Telegram и повторяется следующим запуском. `operations_monitor_states` хранит курсор чтения; первый запуск по умолчанию захватывает только последние 15 минут и не отправляет всю историю проекта.

## Настройка

Откройте диалог с ботом и обязательно отправьте ему `/start`. Затем добавьте в `.env`:

```dotenv
OPERATIONS_TG_CHAT_ID=личный_numeric_chat_id
OPERATIONS_TG_BOT_TOKEN=
OPERATIONS_TG_PROXY_URL=
OPERATIONS_TG_INCLUDE_SUCCESSES=true
```

Пустой `OPERATIONS_TG_BOT_TOKEN` использует `WB_TG_BOT_TOKEN`, пустой proxy — `WB_TG_PROXY_URL`. Групповой `WB_TG_CHAT_ID` не используется: личный получатель задаётся отдельно.

После `/start` узнайте ID без передачи токена сторонним ботам:

```bash
python -m operations_bot --show-chat-ids
```

Команда выведет последние личные чаты в JSON. Скопируйте значение `chat_id` в `OPERATIONS_TG_CHAT_ID`. Если список пуст, ещё раз отправьте боту `/start` и сразу повторите команду.

Проверка вручную:

```bash
python -m operations_bot
```

Production-запуск выполняет `wbozon-operations.timer`. Не запускайте уведомления напрямую из marketplace workers: недоступность Telegram не должна менять их итоговый статус.
