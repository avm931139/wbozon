# Telegram-отчёты WB и Ozon

Модуль не обращается к API маркетплейсов и не изменяет загруженные остатки: читает синхронизированную PostgreSQL, формирует текстовые WB-отчёты и Excel-файлы остатков WB/Ozon, затем отправляет их в одну группу из `WB_TG_CHAT_ID`. Текстовое расписание может запускаться вместе с WB-синхронизацией через корневой `main.py`; Excel-файлы вызываются отдельной командой из cron.

## Что отправляется

- утром в `WB_TG_MORNING_TIME`: прошлый день и текущий месяц по вчера включительно, реклама, остатки, обращения и состояние синхронизации;
- каждые `WB_TG_OPERATIONAL_INTERVAL_SECONDS`: текущие заказы, выкупы, возвраты, реклама, остатки и состояние загрузчика;
- заказы считаются по дате заказа, отмены — отдельно по дате регистрации отмены, выкупы и возвраты — по дате соответствующей операции;
- оперативные показатели явно помечаются как предварительные, пока финансовый отчёт WB не покрывает период.

История хранится в `wb_telegram_deliveries`. Уникальные ключи дня и интервального окна защищают от дублей после перезапуска. Ошибочную отправку процесс повторит, успешную — нет.

## Структура модуля

- `client.py` — вызов Telegram Bot API и разбиение длинных сообщений;
- `reports.py` — расчёт и форматирование отчётов по данным PostgreSQL;
- `dispatcher.py` — резервирование доставки, отправка и запись результата;
- `stock_reports.py` — формирование WB/Ozon `.xlsx` полностью в оперативной памяти;
- `scheduler.py` — утреннее и интервальное расписание;
- `__main__.py` — отдельная точка запуска `python -m telegram_bot`.

## Настройка и запуск

1. Создать бота через BotFather и добавить его в группу.
2. Записать токен в `WB_TG_BOT_TOKEN`, отрицательный ID группы — в `WB_TG_CHAT_ID`.
3. Выполнить `python -m alembic upgrade head`.
4. Проверить: `python -m telegram_bot --once operational`.
5. Запустить синхронизацию и расписание вместе: `python main.py`.

Отдельный запуск только расписания отчётов: `python -m telegram_bot`. Запуск только синхронизации без Telegram: `python main.py --sync-only`.

Разрешённые пользователи не используются: модуль не принимает команды и отправляет сообщения только в настроенный `chat_id`. Для принудительной ручной повторной отправки есть `--force`.

Для просмотра доступных режимов: `python -m telegram_bot --help`.

## Excel-файлы остатков через cron

Команда читает ежедневные срезы из PostgreSQL, создаёт два Excel-файла полностью в памяти и отправляет их как документы. На файловую систему сервера отчёты не записываются.

- дата отчёта — текущая дата в `Europe/Moscow`; при запуске в 09:00 используется срез на 00:00 этого же дня;
- `wb_stocks_YYYY-MM-DD.xlsx` содержит листы FBS и FBO;
- `ozon_stocks_YYYY-MM-DD.xlsx` содержит листы «По складам» и «Агрегат»;
- складской лист Ozon включает ID, понятное название склада и кластер;
- строки с `quantity = 0` для WB и `present = 0` для Ozon в Excel не включаются;
- файлы создаются через `BytesIO`, после отправки удалять на сервере нечего.

```bash
python -m telegram_bot --once stock-files
```

Для повторной отправки конкретной даты:

```bash
python -m telegram_bot --once stock-files --date 2026-08-19 --force
```

Пример ежедневного запуска в 09:00 по Москве:

```cron
CRON_TZ=Europe/Moscow
0 9 * * * cd /path/to/wbozon && .venv/bin/python -m telegram_bot --once stock-files
```

WB и Ozon имеют независимые ключи доставки. Если отправка одного файла завершится ошибкой, следующий запуск не продублирует уже успешно отправленный файл.

Если срез WB или Ozon за текущую московскую дату отсутствует, бот отправляет в группу предупреждение с датой и названием отсутствующего источника. Предупреждение также защищено от повторной отправки за одну дату; файл по доступному источнику отправляется независимо.

## Диагностические уведомления

Команда `python -m healthcheck` использует тот же Telegram-клиент и журнал `wb_telegram_deliveries`. Новый набор ошибок отправляется один раз, неизменные ошибки не повторяются каждые пять минут. После устранения всех проблем отправляется сообщение о восстановлении.
