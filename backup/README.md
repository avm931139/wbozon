# Резервное копирование

Модуль создаёт дамп PostgreSQL в custom format, проверяет его через
`pg_restore --list` и вместе с `data/`, `.env` и backup-конфигурацией отправляет
его в зашифрованный репозиторий Restic. Пароль PostgreSQL передаётся дочерним
процессам только через окружение, а не через командную строку.

## Гарантии

- принимается только внешнее хранилище (`sftp:`, `s3:`, `b2:`, `rest:` и т. п.);
- пароль Restic должен находиться в отдельном файле с правами `0600`;
- ежедневная ротация: 7 daily, 5 weekly, 12 monthly;
- после каждого backup читается 5% репозитория для проверки целостности;
- раз в месяц последний снимок разворачивается в отдельную одноразовую БД;
- имя проверочной БД обязано содержать `restore`, `backup` или `test` и не может
  совпадать с production-БД;
- результаты пишутся атомарно в `data/backup/*.json`; healthcheck контролирует
  их свежесть, а существующий operations bot доставляет ошибку в личный Telegram.

Снимок не считается внешним backup, если Restic-репозиторий расположен на том же
диске VPS. Пароль Restic нужно отдельно сохранить в менеджере паролей: без него
зашифрованную копию невозможно восстановить, а хранить его только внутри этой же
копии бессмысленно.

## Расписание

- `wbozon-backup.timer`: ежедневно в 04:40 МСК с jitter до 10 минут;
- `wbozon-backup-verify.timer`: первого числа месяца в 05:30 МСК с jitter до
  15 минут.

Полная установка, первый запуск и аварийное восстановление описаны в
[`docs/VPS_RUNBOOK.md`](../docs/VPS_RUNBOOK.md).
