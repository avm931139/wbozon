# Карточки товаров и локальное хранилище медиа

`product_catalog` читает уже синхронизированные карточки WB, Ozon и Яндекс Маркета, приводит фотографии, видео и характеристики к общей схеме, сохраняет версии карточек и скачивает медиа на VPS.

```bash
python -m product_catalog
python -m product_catalog --no-download
python -m product_catalog --download-limit 100
```

## PostgreSQL

- `marketplace_product_media` — исходная ссылка, площадка, карточка, тип, роль, порядок, локальный путь, MIME, размер, SHA-256 и статус скачивания;
- `marketplace_product_attributes` — характеристики карточек каждой площадки;
- `marketplace_product_catalog_snapshots` — новая запись только при изменении содержимого карточки, медиа или характеристик;
- `product_catalog_sync_runs` — журнал обработки и ошибок.

Каждая запись связана с `master_products` через `master_product_id`, но исходная площадка и исходный ID не теряются. Исчезнувшие из кабинета медиа и характеристики не удаляются: они получают `active=false`.

WB передаёт одну фотографию сразу в нескольких разрешениях. В локальное хранилище попадает один вариант на позицию: в первую очередь `big`, а остальные размеры используются только как fallback. Все исходные ссылки по-прежнему остаются в `raw_data` карточки.

## Локальные файлы

Корень по умолчанию — `data/product_media/`. Структура:

```text
data/product_media/<marketplace>/<article>/<external_product_id>/<position>_<url_hash>.<ext>
```

Запись атомарная: ответ сначала пишется во временный файл внутри целевого каталога, контролируется максимальный размер, затем файл заменяется через `os.replace`. HTML вместо изображения отклоняется. После скачивания фиксируются размер и SHA-256; существующий файл проверяется перед тем, как пропустить повторную загрузку. Отсутствующий или повреждённый файл скачивается заново.

Файлы не входят в Git. Сейчас локальное хранилище является основным. Позже его можно дополнить S3-совместимым облаком: относительный путь, исходный URL и SHA-256 уже отделены от физического backend хранения.

Настройки:

| Переменная | Назначение | По умолчанию |
|---|---|---:|
| `PRODUCT_MEDIA_STORAGE_DIR` | корень файлов | `data/product_media` |
| `PRODUCT_MEDIA_MAX_FILE_BYTES` | максимум одного файла | 512 MiB |
| `PRODUCT_MEDIA_DOWNLOAD_TIMEOUT_SECONDS` | timeout HTTP | 60 секунд |
| `PRODUCT_MEDIA_DOWNLOAD_WORKERS` | параллельные загрузки | 4 |
| `PRODUCT_MEDIA_DOWNLOAD_LIMIT` | максимум новых файлов за запуск, `0` — все | 0 |
| `PRODUCT_CATALOG_MAX_AGE_SECONDS` | допустимая давность healthcheck | 36 часов |

Ошибки отдельных ссылок сохраняются в строке медиа и дают запуску статус `partial`. Остальные файлы продолжают скачиваться, а следующая ежедневная задача повторяет неудачные ссылки. Одновременный повторный запуск блокируется advisory lock.

Production выполняет нормализацию и докачивание ежедневно в 03:00 МСК после обновления единого справочника в 02:30. Результат поступает в личный операционный Telegram-бот.
