# Документы и бухгалтерия Ozon

Контур работает как независимое задание `python -m ozon --task documents`.
Он не входит в `finances`: существующее задание сохраняет ежедневные начисления,
а `documents` отвечает за разделы **Финансы → Документы** и **Финансы → Баланс**.
Сбой бухгалтерских отчётов не останавливает товары, заказы, остатки или начисления.

## Что синхронизируется

Ozon формирует часть документов асинхронно. Worker создаёт отсутствующие запросы
за каждый полностью завершённый месяц, сохраняет их `code`, обновляет статус через
`/v1/report/list` и `/v1/report/info`, затем скачивает готовые файлы:

- отчёт о взаиморасчётах;
- реестр продаж юридическим лицам;
- отчёты о компенсациях и декомпенсациях;
- позаказный отчёт о реализации.

В PostgreSQL также сохраняются исходные JSON-ответы:

- реестр B2B-продаж;
- отчёт о реализации товаров v2;
- отчёт о выкупленных товарах;
- финансовый отчёт «Доходы и расходы» за закрытые половины месяца;
- скользящий отчёт о балансе за последние 30 дней.

HTTP 404 для завершённого периода фиксируется как штатное отсутствие данных, а
не как авария. Для асинхронного документа создаётся запись запроса со статусом
`not_found`, поэтому заведомо отсутствующий документ не запрашивается каждый день.
HTTP 401/403, лимиты, повреждённые файлы и неожиданный контракт
дают `partial`, ненулевой код процесса и подробность в личном Telegram.

Методы `/v3/finance/transaction/list` и `/v3/finance/transaction/totals` намеренно
не добавлены: Ozon объявил их отключение 8 сентября 2026 года. Их заменяют уже
используемые проектом `/v1/finance/accrual/*` и таблица `ozon_finance_accruals`.

## Таблицы и файлы

- `ozon_accounting_report_requests` — один запрос генерации на тип и месяц;
- `ozon_accounting_reports` — статус, временная ссылка и метаданные отчёта;
- `ozon_accounting_report_files` — локальный путь, размер и SHA-256;
- `ozon_accounting_snapshots` — исходные JSON-отчёты за период;
- `ozon_sync_runs` с `task=documents` — общий результат запуска.

Файлы находятся в `data/ozon/accounting/` и не входят в Git или дамп PostgreSQL.
Для полного восстановления каталог нужно резервировать отдельно.

Ozon отдаёт `finance_realization_posting` как UTF-8 CSV с запятой и без BOM.
Русская версия Excel часто открывает такой исходник одной колонкой. Worker
поэтому сохраняет исходный `.csv` без изменений и рядом атомарно создаёт обычный
`.xlsx`: отдельные колонки, русские названия, закреплённая строка заголовков,
автофильтр и числовые финансовые значения. В БД основным локальным файлом
становится XLSX. Ранее загруженные CSV конвертируются при следующем запуске
`documents`; исходники при этом не удаляются.

Имя основного файла начинается с периода отчёта, например
`2026-07_REPORT_finance_realization_posting_….xlsx`. Для ранее загруженных
документов worker создаёт рядом копию с префиксом `YYYY-MM` и переключает запись
БД на неё; старый файл остаётся на месте.

Downloader не передаёт `Client-Id` и `Api-Key` по временной ссылке. Начальный URL
и каждый редирект должны использовать HTTPS и домен из
`OZON_REPORT_ALLOWED_HOST_SUFFIXES`. Файл записывается атомарно, ограничивается по
размеру и проверяется как XLSX, ZIP, CSV или PDF. Перед пропуском уже существующего
файла сверяются размер и SHA-256.

## Период и повторные запуски

История начинается с `OZON_ACCOUNTING_HISTORY_FROM`, по умолчанию совпадает с
`OZON_HISTORY_FROM`. Месячные документы создаются только за полностью закрытые
месяцы. Первый запуск заполняет всю настроенную историю; последующие пропускают
уже сохранённые запросы и JSON-снимки. Готовых файлов скачивается не более
`OZON_ACCOUNTING_DOWNLOAD_LIMIT=50` за запуск: запас нужен для первого исторического
заполнения, пока временные ссылки не истекли. Асинхронный отчёт может перейти из
`waiting` в `success` только к следующему запуску — это штатно.
Если Ozon завершил запрос со статусом `failed` (например, данные закрытого месяца
ещё не были подготовлены), следующий ежедневный запуск создаёт запрос повторно.
Статусы `success` и `not_found` повторно не запрашиваются.

## Первый запуск на VPS

```bash
cd /home/wbozon/wbozon
./.venv/bin/python -m alembic upgrade head
./.venv/bin/python -m ozon --task documents
```

Первый успешный запуск может создать запросы, но скачать ещё не все файлы.
Повторите команду после формирования отчётов и проверьте журнал. Только после
успешной ручной проверки включите timer:

```bash
sudo cp deploy/systemd/wbozon-ozon@.service /etc/systemd/system/
sudo cp deploy/systemd/wbozon-ozon-documents.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now wbozon-ozon-documents.timer
sudo systemctl start wbozon-ozon@documents.service
sudo journalctl -u wbozon-ozon@documents.service -n 100 --no-pager
```

Timer запускается ежедневно в 04:40 МСК. После успешного production-запуска
добавьте `documents` в `OZON_REQUIRED_TASKS`; healthcheck начнёт контролировать
статус и свежесть через `ozon_sync_runs`.
